# 抖音视频搬运

被 @ 且消息里带抖音分享链接时，解析作品、下载视频，并发回原会话。

判定范围由扩展自己控制：只有**真正 @ 到当前登录账号**的文本消息才会进入流程
（`subscriptions.requireMentionMe: true`），普通消息直接忽略。

## 前置条件

- 本机有 `python3`（3.10 及以上）。
- 本机装了 Chrome：解析脚本用真实浏览器打开作品页、拦截页面自己发出的 `aweme/detail` 响应，
  不自造签名。
- 解析脚本已存在于本机（默认 `scripts/douyin.py`，相对于扩展目录，也可在配置页指定自定义路径）。
- 首次运行时脚本会在 `~/Library/Caches/douyin-video/venv`（Windows 落在 `%LOCALAPPDATA%`）
  自建 venv 并安装 `playwright` / `requests`，约 30 秒；之后复用，不再安装。

## 安装

TraceMemo → 左侧「扩展」→「安装目录」，选择本目录 `douyin-sender/`。

安装完成后：

1. 打开「抖音解析设置」页面，确认 Python 路径与脚本路径；
2. 打开总开关，保存；
3. 在「测试发送」里选目标群、粘贴抖音分享文案，点「测试发送」验证；
   或在微信里 @ 自己发一条带抖音分享链接的文本消息。

扩展默认 `enabled: false`，安装后不会自动对外发送。

配置页的群列表来自本机通讯录，对应权限 `contacts.list`（只读群名与会话 id，不含聊天内容）。

升级同 id 的扩展会替换代码并保留配置；如果新版本**新增了权限**（例如从 image 换成 video），
升级后请「停用 → 启用」一次，让宿主按新 manifest 重新授权。

## 测试发送（配置页）

配置页底部有独立的「测试发送」：

1. 下拉选择目标群（列表来自 `contacts.listGroups`，需要 `contacts.list` 权限）；
2. 粘贴抖音链接或整段分享文案（命令行脚本不需要手动截取 URL）；
3. 点「测试发送」，页面会轮询进度，解析完成后把去水印视频发到该群；
4. 测试路径**不发回执**，避免测试时多一条消息；
5. 测试任务同样计入统计，进度显示在「当前任务」。

设置页可选使用「抖音 Cookie」面板粘贴并保存 Cookie header。宿主通过系统安全存储加密后保存在本机，页面只展示是否已配置，不会回显内容；测试发送与自动解析时在后台使用该 Cookie，未配置时也可回退读取本机 `douyin-cookie` 文件。

## 配置字段

| 字段              | 默认值                   | 说明                                                                   |
| ----------------- | ------------------------ | ---------------------------------------------------------------------- |
| `enabled`         | `false`                  | 总开关；关闭时任何消息都不处理                                         |
| `pythonPath`      | `python3`                | Python 可执行文件，支持 `~`                                            |
| `scriptPath`      | `scripts/douyin.py`      | 解析脚本路径（默认相对于扩展目录，支持 `~` 与绝对路径）                |
| `quality`         | `720`                    | `''` 最高 / `1080` / `720` / `540`；其他值收敛到 `720`                 |
| `showUi`          | `false`                  | 排障开关：显示浏览器窗口以观察最终页面；不保证改变平台响应             |
| 抖音 Cookie       | 未配置                   | 配置页输入后由 Electron `safeStorage` 加密保存                         |
| `ackText`         | `收到，正在解析，请稍候…`| 命中后先回复的文本；留空表示不回执                                     |
| `errorReply`      | `true`                   | 失败时是否在原会话回一条简短说明                                       |
| `includeDirect`   | `false`                  | 是否同时处理私聊                                                       |
| `groups`          | `[]`                     | 群白名单；空数组表示全部群                                             |
| `cooldownSeconds` | `60`                     | 按会话计的冷却，0–3600                                                 |
| `maxFileMB`       | `100`                    | 单文件上限，1–100，不能超过宿主 100 MB 硬限制                          |

保存时写入 `configVersion: 1`；后台最多 1 秒内读到新配置（配置缓存 TTL 1000 ms）。

## 处理流程

1. `message.received` → 判定顺序：总开关 → 自己发的 → 非 text → 未 @我 → 提取链接 → 会话范围 → 冷却。
2. 命中后先回执（`ackText`，默认「收到，正在解析，请稍候…」；留空关闭），再进入解析。
3. `python3 <script> "<链接>" -o <dataDir>/downloads --wait 40 --download-timeout 90 --json --video-only --download`，单次打开作品页并完成解析、下载；图集只返回类型、不下载；进程总超时 420 秒，输出上限 8 MB，`cwd` 为扩展数据目录。
4. 从 JSON 结果中读取作品元数据与 `saved` 绝对路径；校验文件存在、是普通文件、未超过上限。
5. 若结果为图集，记为 `IMAGE_SET` 并按配置处理失败提示；若解析/下载失败，保留脚本返回的错误原因。
6. 发送视频，`dedupeKey = eventId + ':video'`（不再额外发送作品标题文本）。
7. 每个阶段都写 `progress` 快照并记一条日志；配置页每 2 秒刷新一次进度。
8. 无论成败写一条统计（成功/失败分别计数）；失败只记阶段、错误码与去掉 URL / 路径的短原因。
9. 冷却只在**视频发送成功后**写入。

同一会话同时只跑一个任务；同一条消息重复投递时按 `会话 + 链接` 去重。启动时会清理
`<dataDir>/downloads`：只保留最近 20 个文件，并删除 7 天前的文件。

失败文案固定为三种，原因截断到 60 字且不含路径：

- `解析失败：<短原因>`
- `视频过大（<N>MB），已跳过`
- `暂不支持图集`

## 发送通道

视频走宿主的 **video 通道**：`tm.wechat.send({ type: 'video', to, path })`。
原生 Host 以 `{toWxid, type:'video', msg:<路径>}` 提交，所以 `permissions` 里申请的是 `wechat.send.video`。

媒体文件必须落在扩展数据目录或系统临时目录内（宿主会用 `realpath` 复核），扩展名必须是
`mp4/mov/m4v`，大小 1 B–100 MB。所有发送仍要过 Gateway 的权限、
授权与限流：同一扩展 60 秒最多 10 条，两条之间至少 2 秒。

## 限制

- 只处理视频；图集（`type: 'image'`）不下载，按配置回「暂不支持图集」。
- 单个文件 ≤ 100 MB，超过不发送。
- 冷却按会话计，冷却期内同一会话的新链接会被忽略。
- 事件投递是「至多一次」：TraceMemo 未运行期间的消息不会补发。
- 脚本路径必须在本机真实存在；路径错误时错误文案会提示检查 Python 路径。
- 解析依赖抖音页面结构，脚本自身失效时扩展只能报「解析失败」。

## 排障：`页面已加载（NNNKB）但未发出 detail 请求`

这是浏览器打开了页面，但没有捕获到 `aweme/detail` 的作品数据。仅凭这一条错误不能判断作品已删除；页面也可能是作品壳、推荐页或平台验证状态。先看 `--debug` 现场中的页面标题、地址和截图。扩展不会并发启动第二次解析；测试发送失败时会在页面显示阶段、错误码和去掉 URL / 本地路径后的短原因。

仍需手动复试时：

1. 先等一会儿再尝试，避免同一作品短时间内重复请求；
2. 配置页勾选「显示浏览器窗口」后重新测试，观察最终停留页面；
3. 命令行单独验证时使用同一份脚本，避免与扩展并发运行：

```bash
python3 scripts/douyin.py \
  "https://v.douyin.com/xxxxxx/" --json --wait 40 --show-ui
```

## 进度与统计

- 回执：命中后先发一条 `ackText`，默认「收到，正在解析，请稍候…」；留空则不回。
- 进度：存储键 `progress`，结构 `{stage,status,startedAt,updatedAt,awemeId,errorType,errorMessage}`。
  配置页每 2 秒读取一次，显示「已接收 / 解析 / 下载 / 发送 / 补发文案 / 完成」，
  失败时显示失败所在阶段与错误码。
- 统计：存储键 `stats`，结构 `{dateKey,todayTotal,todaySuccess,todayFailure,lastJobs[]}`；
  失败也计数，`lastJobs` 保留最近 20 条（含阶段与错误码）。
- 页面顶部「统计」显示今日总计 / 成功 / 失败；表格展示最近 8 条。

## 隐私

- 分享链接会交给本机脚本，由脚本访问抖音页面；扩展本身不向任何第三方发请求。
- 下载的视频存放在扩展数据目录 `downloads/` 下，发送后不自动删除（按上面的规则轮转清理）。
- 统计只保存时间、作品 id、阶段、成败、错误码，**不含** URL、标题、作者、会话 id。
- 日志只写阶段与错误类型。
