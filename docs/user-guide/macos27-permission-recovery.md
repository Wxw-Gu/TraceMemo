# macOS 更新后读不到微信数据：权限恢复

本文只处理一种情况：**TraceMemo 之前能连上微信数据库，升级 macOS 或更新 TraceMemo 之后读不到了**。

正常使用、没有出现权限提示的用户，不需要做任何操作。

---

## 1. 适用版本与典型表现

### 适用系统

- macOS 27 及更高版本（本文的主要场景）
- 从 macOS 26 或更早版本升级到 macOS 27 之后首次启动 TraceMemo
- TraceMemo 2.5.2 及更高版本（更早的版本升到新版时同样可能出现），且此前已经成功连接过一次微信数据库

如果你从来没有成功连接过，卡在「自动获取密钥」这一步，那不是本文的场景，请看[第一次使用](./getting-started.md)里的密钥获取流程。

### 典型表现

出现下面任意一条，且**微信数据目录确实存在**，再按本文处理：

- 连接页提示「无法读取微信数据库」，错误码 `DATABASE_PERMISSION_DENIED`
- 提示「无法打开数据库」，但微信能正常登录、聊天记录能正常查看（权限不足有时会被包装成「打不开」）
- 昨天还能用，更新应用后重启就连接失败，期间没有换账号、没有迁移数据目录
- 「系统设置 → 隐私与安全性 → 完全磁盘访问权限」里，TraceMemo 的开关是**打开**的，但应用仍然读不到

如果提示的是「**密钥与当前账号不匹配**」，那不属于本文范围 —— 那是密钥和账号对不上，按[常见问题与排查](./troubleshooting.md#连接微信失败)里的密钥流程处理。

判断数据目录是否真的存在，可以在终端执行（把路径里的账号目录换成你自己的）：

```bash
ls ~/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files
```

能列出账号目录，说明数据是完整的，问题出在**权限**，不在文件。

> 终端能读到、TraceMemo 读不到，是完全正常的情况。macOS 的隐私权限按「应用」判定，不按「用户」判定，两者走的是两套不同的检查。所以「终端能读」不能用来排除权限问题。

---

## 2. 为什么更新应用之后会失去访问权限

一句话：**macOS 认的是应用文件的「指纹」，不是应用的名字。**

TraceMemo 目前发布的 macOS 版本没有使用 Apple 开发者证书签名，用的是 ad-hoc 签名（相当于临时签名，没有可核验的开发者身份）。这种签名没有稳定的身份标识，系统只能靠应用二进制的指纹来记住「这是哪个应用、你给它授过什么权」。

每次发布新版本，二进制内容通常会变，指纹随之改变。系统看到的是一个指纹不同的新应用，之前那条授权记录对不上号，于是按「未授权」处理 —— 微信数据在另一个应用的沙盒容器里，读取被拒绝，连接页就报「无法读取微信数据库」。

几个容易误解的点：

- **不是数据库损坏**。数据一直好好的，微信自己也能正常读写。
- **不是密钥失效**。密钥还在本地，验证也没问题，卡住的是「打开文件」这一步。
- **不是 macOS 27 单独引入的缺陷**。指纹变化导致授权失效，在更早的 macOS 上也会发生；macOS 27 上反馈更集中，但没有做过版本对照验证。
- **重装应用通常无效**。重装会生成同样的新指纹，旧授权依旧对不上。

## 3. 一次性终端修复

先**完全退出** TraceMemo，不是关窗口，是退出进程：

- 菜单栏 `TraceMemo → 退出 TraceMemo`，或按 `Command + Q`
- 托盘/菜单栏图标里如果有「退出」，也点一次
- 确认没有残留：打开「活动监视器」，搜索 `TraceMemo`，有残留就选中并点「退出」

然后打开「终端」（`应用程序 → 实用工具 → 终端`），执行：

```bash
tccutil reset SystemPolicyAppDataDetailed com.tracememo.app
```

再执行：

```bash
tccutil reset SystemPolicyAllFiles com.tracememo.app
```

两条命令都只影响当前用户，不需要 `sudo`。

执行后**不会**看到「授权成功」之类的提示。这条命令的作用是**删掉旧记录**，不是**发放权限**。删除之后，需要你在系统设置里重新授权一次（见第 5 节）。

### 如果提示服务名无效

终端报下面这类错误：

```
tccutil: Invalid service name
```

说明当前系统不认识 `SystemPolicyAppDataDetailed` 这个服务名。改用 Apple 公开文档里的写法：

```bash
tccutil reset SystemPolicyAppData com.tracememo.app
```

`SystemPolicyAppDataDetailed` 是否在所有 macOS 27 版本上都可用，尚未逐一验证。两种情况的效果一样：都是清掉 TraceMemo 在这类「其他应用数据」权限上的旧记录。无论用哪条，都还是要走第 5 节手动重新授权。

---

## 4. 两条命令分别管什么

| 命令 | 管的是 | 什么时候需要 |
| --- | --- | --- |
| `SystemPolicyAppDataDetailed`（或 `SystemPolicyAppData`） | 访问**其他应用沙盒容器内文件**的授权。微信数据正好在这个范围内 | 主要用这条。它清掉的是「读微信容器」这一层的旧记录 |
| `SystemPolicyAllFiles` | **完全磁盘访问权限**的授权记录 | 系统设置里 TraceMemo 的开关看起来是开的、但实际不生效时，用它清掉整条记录重来 |

适用范围：

- 两条都只针对 `com.tracememo.app` 这一个应用，不影响微信、不影响其他软件
- 都只影响当前登录的 Mac 用户
- 都只是**删除记录**，不会自动给权限，也不会把权限收得更紧
- 不要在命令里用 `All`（例如 `tccutil reset All`）—— 那会清掉这台机器上**所有应用**的所有隐私授权，微信、输入法、录屏、麦克风全要重新授权一遍，代价远大于收益
- 不要用 `sudo`。系统级重置需要重启、影响所有用户，和本文的场景无关

两条命令可以只执行第一条先试。第一条无效、或系统设置里的开关状态明显不对，再执行第二条。

---

## 5. 执行命令后手动重新授权

1. 打开 **系统设置 → 隐私与安全性 → 完全磁盘访问权限**
   （不同系统版本的条目名称略有差异，位置都在「隐私与安全性」下）
2. 在列表里找到 **TraceMemo**
   - 如果还在列表里：选中，点列表下方的 `−` 删除
   - 如果已经不在列表里：跳过这一步
3. 点 `+`，在弹出的文件选择器里进入 **应用程序**，选中 **TraceMemo.app**，点「打开」
4. 确认 TraceMemo 右侧的开关是**打开**状态
5. **完全退出 TraceMemo 再重新打开**。授权只在应用下次启动时生效，当前正在运行的进程拿不到新权限

如果第 3 步选不到应用，或添加后开关立刻又关掉，先确认应用确实在 `/Applications/TraceMemo.app`，而不是在下载目录、挂载的 dmg 镜像里、或某个临时文件夹里。从 dmg 直接运行的副本每次挂载路径都不同，系统无法稳定记住授权。

## 6. 完全不使用终端的做法

不想碰终端也可以，只是机制上少了一步，成功率没有统计数据。

### 步骤

1. 完全退出 TraceMemo（`Command + Q`，再从活动监视器确认没有残留进程）
2. 打开 **系统设置 → 隐私与安全性 → 完全磁盘访问权限**
3. 在列表里选中 **TraceMemo**，点 `−` 删除
4. 完全退出「系统设置」（`Command + Q`）
5. 重新打开「系统设置」，回到同一页面，点 `+`，添加 `/Applications/TraceMemo.app`
6. 确认开关已打开
7. 重新启动 TraceMemo，回到连接页重试

### 局限性

- **删掉再添加，不一定能清掉底层旧记录**。系统设置里删的是可见条目，某些情况下底层的授权记录仍然存在且指向旧的应用指纹，界面看起来正常、实际依旧不生效。终端那两条命令做的正是清掉这一层。
- **开关是开的，不等于权限生效**。系统偶尔会显示开关已开，但实际判定仍是拒绝。这时只能靠重置记录解决。
- **没有「修复」按钮**。系统设置不提供「重新校验应用」这类操作，能做的只有删除和重新添加。

两步的分工要说清：终端命令负责**清掉旧记录**，本节负责**重新建立记录**。

- 只做本节：旧记录可能还在，界面看着正常、实际不生效。
- 只做终端命令：记录被一起删掉，必须再走本节第 3 到 5 步添加回来，否则权限是空的。
- 已收到的恢复反馈里，成功案例都是两步连着做的。

所以推荐顺序是：第 3 节命令 → 本节删除并重新添加 → 重启应用。

## 7. 如何重启并验证

授权改完必须**重启进程**，不是重新打开窗口。

### 从 Dock 退出

1. 在 Dock 里找到 TraceMemo 图标
2. 右键（或双指点按）→ **退出**
3. 确认图标下方的运行指示点消失
4. 重新点图标启动

### 从 Finder 退出

1. 打开「活动监视器」（`应用程序 → 实用工具 → 活动监视器`）
2. 搜索框输入 `TraceMemo`
3. 选中 `TraceMemo` 进程，点左上角的 `×`，选「退出」
4. 确认列表里已经没有 TraceMemo
5. 打开「访达 → 应用程序」，双击 **TraceMemo**

### 验证是否恢复

启动后回到连接页，看这几点：

- 不再出现「无法读取微信数据库」
- 账号、联系人、会话能正常加载
- 随便搜一个关键词，能返回结果

只看到「已连接」但列表是空的，不算恢复，按第 8 节收集信息。

## 8. 修复失败要提供什么

按顺序做一遍，仍然失败，把下面这些信息一起提交：

1. **系统版本**：苹果菜单 → 关于本机，记录版本号（例如 macOS 27.x）和芯片（Apple Silicon / Intel）
2. **TraceMemo 版本**：应用内「设置 → 关于」，或菜单栏 `TraceMemo → 关于 TraceMemo`
3. **微信版本**：微信 `设置 → 关于微信`
4. **连接页的完整提示原文**，包括错误码。有截图更好
5. **脱敏诊断摘要**：连接页上的「复制脱敏诊断摘要」按钮，点一下会复制到剪贴板，直接粘贴到反馈里
6. **第 3 节命令的实际输出**，包括报错。如果提示 `Invalid service name`，一定要写出来
7. **系统设置里 TraceMemo 那条记录的状态**：在不在列表里、开关是开还是关

诊断摘要里不包含聊天内容、数据库密钥、完整文件路径，可以放心贴出来。

## 9. 不需要重新取密钥，也不要动微信数据

这一步很重要，能省掉大量无用操作。

- **不需要重新获取 WCDB 密钥**。密钥保存在本地，本次故障里它一直是正确的。重新走一遍密钥获取流程，只会多一次监听微信登录的动作，不会改变权限结果。
- **不要删除微信数据库**。数据完好，删了就是真的没了。
- **不要删除 TraceMemo 的配置目录**。里面有账号指向、密钥、索引，删掉要全部重来。
- **不要用 `sudo` 运行 TraceMemo**。以 root 运行会换一个进程身份，权限判定更混乱，还会让配置文件属主变成 root，后续正常启动反而出问题。
- **不要 `chmod` / `chown` 整个微信目录**。改了会影响微信自身的读写，属于制造新问题。
- **不要为了这个问题关闭 SIP**。SIP 管的是系统完整性保护，和「某个应用能不能读另一个应用的容器」不是一回事。关闭 SIP 不解决这个权限判定，还会降低整机安全性。SIP 相关说明见[关闭 SIP 教程](../mac-disable-sip.md)，那是密钥获取流程里的独立话题。

### 顺带区分：这不是 Frida 附加失败

两类问题长得像，处理方式完全不同：

| | 数据库访问权限问题（本文） | 密钥获取/进程附加问题 |
| --- | --- | --- |
| 出现时机 | 已经连过、升级后重新打开 | 首次连接，或重新获取密钥时 |
| 界面提示 | 「无法读取微信数据库」`DATABASE_PERMISSION_DENIED` | 监听超时 `CAPTURE_TIMEOUT`、内存扫描失败，或提示无法绑定微信进程 |
| 数据目录检测 | 显示已检测到 | 通常在更早的步骤就失败 |
| 处理方向 | 系统设置里重新授权 | 检查微信是否停在登录页、是否需要管理员授权、微信版本是否适配 |

如果你的现象是「点了自动获取密钥，一直等到超时」，那走的是右边一列，不是本文的权限问题。

---

## 10. 这只是当前故障的恢复方案

说清楚边界：

- 本文解决的是**已经发生**的授权断裂，不改变应用的签名方式。
- 只要发布包仍然是当前这种 ad-hoc 签名，**下一次更新后仍可能再次发生**。
- 出现时，重复第 3 到 5 节即可，通常不需要重装、不需要重新取密钥。
- 彻底解决需要发布端改用稳定的开发者签名并完成公证，这属于打包流程的改动，不在用户侧。

正常使用、没有出现问题的用户，不需要提前做任何权限设置。授权不是安装前置条件。
